# 시연 영상 스크립트 (3분 이내)

목적: 결과보고서 제출용 시연 영상. 대회 가이드 기준 3분 이내, 유튜브 업로드 후 링크 기재.

## 방향: "문서 읽기"가 아니라 "실제 사용" 위주로

이전 버전은 README/architecture.md/results.md 화면을 띄우고 대사를 읽는 슬라이드형 구성이었다. 이건 소프트웨어가 실제로 동작하는 걸 보여주지 못한다. 이번 버전은 화면의 80% 이상을 **터미널 실행 + 실제 AI 채팅 화면**으로 채운다. `.md` 파일은 필요할 때 1~2초 잠깐 보여주는 보조 자료로만 쓴다.

대사는 "읽는 대본"이 아니라 "말할 요점"이다. 그대로 읽으면 오히려 부자연스럽다 — 자기 말로 편하게 설명하면 된다.

## 구성 (총 3분 목표)

### 0:00–0:20 — 문제 상황 (터미널)

화면: 실제 session log 파일(`examples/groq_model_migration_session/session.txt`, 또는 본인이 가진 진짜 대화 로그)을 터미널이나 에디터에서 스크롤하며 보여준다.

말할 요점: "AI랑 코딩하다가 대화가 길어지면 이런 일이 생겨요. 세션이 압축되거나 새 세션으로 넘어가야 하는데, 그러면 지금까지 뭘 했는지 다시 설명해야 하죠."

md 화면 없이 바로 시작한다.

### 0:20–1:00 — 실제 실행 (터미널, 실시간)

화면: 터미널. 미리 녹화 끊지 말고 실제로 명령을 치는 걸 그대로 보여준다.

```bash
pip install -e .
context-continuity-engine examples/groq_model_migration_session/session.txt --raw | pbcopy
```

말할 요점: "이 명령 하나로 세션 로그가 분석돼서 요약된 context가 클립보드에 복사돼요. 원본은 1311 token인데 지금 486 token으로 줄었고, 이 안에 다음 세션에서 필요한 정보 — 목표, 결정, 실패했던 것, 지금 상태, 다음 할 일 — 가 다 들어있어요."

(선택) `python3 scripts/run_comparison.py && cat examples/groq_model_migration_session/comparison_result.md` 로 baseline 비교 수치를 잠깐 보여줘도 좋다.

### 1:00–1:50 — 진짜로 붙여넣어서 써보기 (이게 핵심 장면)

화면: 브라우저에서 Claude.ai나 ChatGPT 같은 실제 AI 채팅 새 창을 연다. 방금 클립보드에 복사된 Working Context를 그대로 붙여넣고, 그 정보가 있어야만 답할 수 있는 질문을 던진다. 예: "지금까지 뭘 했고 다음에 뭘 해야 해?" 또는 "왜 그 결정을 했지?"

AI가 원본 대화를 하나도 못 봤는데도 붙여넣은 context만으로 정확히 답하는 걸 그대로 보여준다.

말할 요점: "새 세션에 전체 대화를 다 복사하면 token을 그대로 다 쓰는 거고, 아무것도 안 넘기면 처음부터 다시 설명해야 해요. 이 도구는 그 중간을 자동으로 골라주는 거예요."

이 장면이 "진짜 소프트웨어가 실제로 문제를 해결하는" 유일한 증거 장면이라 가장 중요하다.

### 1:50–2:20 — 정직하게 한계 언급 (짧게, 구두로)

화면: 터미널이나 GitHub 그대로 두고, `docs/results.md`는 스치듯 1~2초만 보여줘도 충분하다.

말할 요점: "가장 단순하게 최근 대화만 남기는 baseline보다는 재구성 품질에서 앞서요. 근데 모든 turn을 짧게 자르기만 하는 다른 baseline한테는 token 효율에서 아직 못 이겨요. 이건 숨기지 않고 코드랑 문서에 그대로 남겨뒀어요."

### 2:20–2:50 — 저장소/테스트/거버넌스

화면: GitHub 저장소, Issues 탭, 병합된 PR을 실제로 클릭해서 보여준다. 터미널로 돌아와서:

```bash
python3 -m unittest discover -s tests
```

`OK`로 끝나는 장면까지 포함.

말할 요점: "테스트 94개가 다 통과하고, 기능마다 브랜치 나눠서 PR로 머지했어요. 결정마다 이유도 문서로 남겨뒀고요."

### 2:50–3:00 — 마무리 (본인 말로, 짧게)

말할 요점: 왜 이 문제를 풀고 싶었는지, 다음에 뭘 더 하고 싶은지 한 문장씩. 대본 없이 진짜 하고 싶은 말을 하는 게 제일 자연스럽다.

## 녹화 체크리스트

- [ ] 화면 녹화 도구 준비 (`Cmd+Shift+5`)
- [ ] 터미널 글씨 크기 키우기(심사위원이 봐야 함)
- [ ] 명령을 미리 쳐보고 리허설 1회 — 단, 화면은 진짜로 실행하는 것으로 녹화(가짜 캡처 아님)
- [ ] 브라우저에 새 AI 채팅 창을 미리 하나 띄워둔다(1:00 장면 전환이 빨라야 함)
- [ ] `python3 -m unittest discover -s tests` 결과가 `OK`로 끝나는 장면 포함
- [ ] GitHub 저장소의 Issues/PR 화면 포함(팀워크 항목)
- [ ] `.md` 파일 화면은 합쳐서 5초 이내로 제한 — 터미널/브라우저 화면이 대부분이어야 함
- [ ] 3분 이내로 자르기
- [ ] 유튜브 업로드(공개 또는 링크 공개) 후 링크를 결과보고서에 기재
