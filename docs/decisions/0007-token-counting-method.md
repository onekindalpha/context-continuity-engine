# 0007. token 계산 방식

## 상태

확정(근사치)

## 결정

`tiktoken` 등 정확한 tokenizer 라이브러리를 쓰지 않는다. 문자 종류별 근사 계수(한국어/한자 1.5자당 1 token, 그 외 4자당 1 token)로 추정한다.

## 이유

이 환경에 `tiktoken`이 설치돼 있지 않고, 설치하려면 외부 패키지 추가가 필요하다(AGENTS.md 규칙 2: dependency 추가 전 이유 기록). 지금 단계에서는 baseline과 proposed 사이의 **상대적** token 차이를 비교하는 것이 목적이지 절대값의 정밀도가 목적이 아니다. 근사치로도 두 방식의 우열 비교는 가능하다.

## 알려진 한계

- 실제 모델별 tokenizer(BPE)와 다르다. 절대 token 수는 부정확할 수 있다.
- 같은 근사 함수를 baseline과 proposed 양쪽에 동일하게 적용하므로 상대 비교의 방향성은 유지된다고 가정한다. 이 가정은 검증되지 않았다 — 확인되지 않음.

## 재검토 조건

정확한 비용 수치가 필요해지면(예: 결과보고서에 절대 금액을 적어야 할 때) `tiktoken` 추가를 재검토한다.
