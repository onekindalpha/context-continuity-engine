# 0006. 규칙 기반 추출기를 첫 baseline으로 구현

## 상태

확정

## 평가 목적

Task Context Analysis 실제 동작(SessionLog → ContextItem)을 구현해야 한다. LLM 사용은 허용됐지만 필수는 아니었다.

## 결정

첫 구현은 LLM 호출 없이 규칙 기반(키워드/정규식/시간 간격 휴리스틱)으로 만든다.

## 이유

1. 이 세션 환경에 사용 가능한 LLM API 키가 없다. 호출 코드를 작성해도 실행/검증이 불가능하다. 실행하지 않은 LLM 결과를 실행됐다고 적으면 근거 없는 결과를 기록하는 것이다(AGENTS.md 규칙 7).
2. `retention_action`은 이미 "LLM이 자유롭게 판단하지 않고 규칙으로 먼저 구현"하라는 요구가 있었다. 같은 원칙을 추출 단계에도 적용하면 파이프라인 전체가 오늘은 결정적(deterministic)이고 재현 가능하다.
3. 규칙 기반 결과는 fixture에 대해 즉시 실행하고 검증할 수 있다. `context_analysis.json`/`context_analysis.md`를 실제로 생성해서 완료 조건을 채울 수 있다.

## 알려진 한계

- turn 단위로만 분류한다. `docs/decisions/0004`의 수동 예시처럼 여러 turn을 하나의 item으로 합치지 않는다. 결과 item 수와 내용이 수동 예시(14개)와 다를 수 있다.
- `summary`는 의미 요약이 아니라 원문 앞부분을 잘라낸 값이다. 의미 요약에는 LLM 또는 사람이 필요하다.
- 카테고리 분류 키워드는 이번 fixture의 실제 표현을 참고해서 만들었다. 다른 세션에 그대로 적용했을 때 정확도는 확인되지 않았다.

## 다음 단계로 남기는 것

LLM 기반 추출기는 이 규칙 기반 baseline과 같은 출력 schema를 따르는 별도 구현으로 나중에 추가한다. 오늘은 만들지 않는다.
